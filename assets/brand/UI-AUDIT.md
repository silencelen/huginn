# Huginn UI audit — 2026-10-13

Four read-only audits of the current product, one each for the Android phone app, the Compose desktop app, the shared component library and every terminal surface, compared against BRAND.md. Nothing here was run on a device; everything is read from the code with file references. The short version: the brand is in the token file but not yet in the product. The apps still draw attention in red, use the accent for six different things, show idle five ways, word needs-you nine ways, and build rows on a dozen paddings and nine radii. The terminal has the same problems in text form. None of it is hard to fix, and most of it is one shared layer between the brand and the screens that does not exist yet.

Source audits: the phone app, the desktop app, the shared `:ui` library and the terminal surfaces, read against [`BRAND.md`](BRAND.md). The rendered twin of this document is the "Huginn UI Audit" page.

## 3. The missing layer: a UI system between the brand and the screens

The brand book says what the colours and type are. It does not say what a row is. These rules are that layer; every finding above resolves into one of them.

| Rule | Decision |
|---|---|
| State | One function, stateColor(state), backed by HuginnColors, and one word table: working · needs you · waiting · shell · ok · error · info. Wire words map once: running to working, attention to needs you, idle to waiting. An 8 dp dot for live states, a 6 dp quiet dot for waiting and offline. Needs-you is stateAttention on every surface: rows, rail, status line, header, tab, question bar, widget, tray, Rounds. Red is failure only. |
| Accent | Primary means live and you: the working dot and pulse, the selected item, links, the cursor, and the one filled button on a screen, which is Send. Never a section label, never decoration, never a warning, never online. Stop and Interrupt are plain outlined buttons. Soft verbs are onSurfaceVariant; destructive verbs and their confirm buttons are error. |
| Severity | Meters and thresholds use one ramp: normal is outline, warning is stateAttention, critical is error. Context at 80 percent, disk at 80 percent, plan meters, headroom WARN and RED all read it. |
| Surfaces | Tier 0 (surfaceContainerLowest) for code wells and the terminal; tier 1 (Low) for list rows and bubbles; tier 2 (Container) for cards; tier 3 (High) for dialogs, menus and the active tab; tier 4 (Highest) for chips. No surfaceVariant alphas. Dividers are outlineHairline; strokes are outline. |
| Shape and space | Radius 6 for chips, 8 for cards and rows, 12 for sheets and dialogs, circle for dots and the send button. Spacing on 4/8/12/16/20/24. Leading inset 16 on the phone, 12 on the desktop, nothing else. |
| Row | One row anatomy for sessions, chats, projects, members, apps, devices and archived items: dot or icon, title (bodyMedium, mono where it is a name), one meta line (labelSmall onSurfaceVariant), trailing time or state word. Phone 16/10, desktop 12/6. Selected row is surfaceContainerLow plus SemiBold, nothing else. One ListHeader (Title Case, labelLarge, with its count and verb), one EmptyState (title, line, one text button), one Dialog (titleSmall, destructive verb in error), one Menu (the house menu everywhere, including the chat top bar). |
| Composer | One shared composer for Chat, Session and Terminal: the outlined 20 dp field, attach and mic as plain icons, Send as the one filled circle, Stop as a plain outlined circle. The terminal's key row keeps its chips but in LocalMonoStyle without the "↦". |
| Type | Plex Mono and Sans once bundled (BRAND.md section 5 roles). Until then: all mono text through LocalMonoStyle, never labelSmall with Monospace. Section headers Title Case, no uppercase tracking. Glyph affordances become Material icons; the glyph table is for terminals. |
| Icons | Outlined on every bar and rail, Filled only for the active bottom-bar item. One icon per concept: Devices and Local do not share one. |
| Notifications and widgets | setColor(primary) on every notification; the raven PNG on Linux; channels named Needs you, Finished, Watching, plus Proposals; the widgets on GlanceTheme(ColorProviders(light, dark)) from the scheme with the same state words and dots as the Sessions list. |
| Terminal | One state table shipped as data (7-bit and Unicode glyphs plus the seven words) read by every renderer, the help footer, the title hook and the Telegram formatter. One colour guard (TTY and NO_COLOR) in bash and PowerShell. One line grammar: "(o> huginn — surface" first line, "  .  " separator, "->" arrows, blank-line padding, a count footer, lowercase except needs you. Telegram leads with the glyph, not an emoji. The two help screens generated from one table. |

## 4. Screens ranked

The three platform audits each named their top five. Merged, by leverage:

1. Sessions list (phone) and the desktop frame's state vocabulary (rail, rows, status line, tray). This is where red-means-attention, the dot sizes and the tooltip-only words live, and the widget reuses the phone's code. Fix the state language here first and half of section 2 follows.
2. Session screen on both platforms: four stacked strips, two attention colours on one screen, three composers, red Interrupt, text pickers that differ from Chat's chips, a rainbow Overview.
3. Status (phone) and the meters: the one place to define the severity ramp, plus the favicon card.
4. Projects on both: shared composables that bring their own metrics, a yellow dot and ▾▸ glyphs into frames built on other numbers. The pane that reads most like a different app.
5. Settings and setup: the first screens a new user sees; pill rows with selection dots, filled buttons for harmless actions, "›" glyphs, long copy.
6. Chats and Chat: pink queued marks, the bolt, host chips, the filled red Stop; the composer that should become the shared one.
7. Notifications and the Fleet widget: the surfaces seen most outside the app, with no brand colour and the wrong channel for proposals.
8. The terminal renderers and Telegram: one table, one guard, no emoji, no shouting.
