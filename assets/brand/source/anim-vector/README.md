# anim-vector — motion for the mark on screens

Five explorations of how the Huginn raven moves, built on the current canonical path
(`assets/brand/raven.svg`). Every file keeps the mark as one `<path id="raven" d="...">`
and references it, so when the mark dimension picks a new raven the swap is one edit
(the generated ones re-read `raven.svg`; run `bash build.sh`).

| id | one line | look at |
|---|---|---|
| `anim-01-blink` | the eye blinks: an ink lid closes over the evenodd hole, 320 ms, irregular cadence; otherwise still | `anim-01-blink/preview.png` (rows: bone / dark / zooms and resting tiles) |
| `anim-02-assemble` | 93 terminal glyphs (`█▓▒░▀▄`, blocks baked as rects) fly in and settle into the silhouette, then the solid mark takes over, 2.0 s | `anim-02-assemble/preview.png` (rows: bone / dark / resting tiles) |
| `anim-03-fly-return` | the raven crouches, opens its wings, lifts into a flight silhouette, exits right, returns from the left and perches: 5 s loop with a 2 s hold; in-app only | `anim-03-fly-return/preview.png` (rows: bone / dark / 64 px) |
| `anim-04-attention-pulse` | tray IDLE → ATTENTION: the raven slides to its badge layout, the badge pops, a ring leaves the raven twice, then rest; 64 px sprite, 10 fps | `anim-04-attention-pulse/preview.png` (rows: 128 / 64 sprite / 24 / 16, the small ones downscaled like a tray) |
| `anim-05-thinking` | three "Claude is working" indicators: (a) falling feather, (b) eye scan, (c) block cursor breathing on the apps' PulseDot clock. Recommendation: (c) | `anim-05-thinking/preview.png` |

Plus `tray-sprite-spec.md`: how `TrayIcons.kt` (Java2D) plays anim-04 - geometry, frame
maths, the 10 fps table (generated by `anim-04-attention-pulse/build.py --table`), the
24 fps variant, memory and behaviour rules.

Ranking after revision, for the owner: **01** for the README hero and the app's idle
state; **05c** for the chat indicator; **04** for the tray; **02** for the splash and the
docs hero; **03** for the desktop reconnecting state and first run (in-app only).

## What each folder holds

- `anim.svg` - the animation as pure SVG + CSS. `anim-inverse.svg` (bone on dark) for
  01, 02, 03 and 05, for a `<picture>` dark source or the app's dark scheme.
- `anim.html` - self-contained preview page: the SVG inlined, no dependencies, with
  `window.seek(t)` (pauses every animation and sets it to t seconds) and `?t=<s>`,
  `?theme=dark`, `?freeze=1` (start paused) and `?static=1` (no animations: the resting
  state) query parameters, so any instant and the resting state can be screenshotted.
- `preview.png` - the contact sheet to review on GitHub; `poster.png` - the resting frame
  as a plain PNG; `fallback.gif` (01, 02) - a GIF of the animation for surfaces that
  rasterise SVG without animation (Slack unfurls, npm / PyPI READMEs, social cards).
- `capture.mjs` - rebuilds those with Playwright through the shared `../capture.mjs`
  (seek, wait two frames, screenshot, label, tile with ImageMagick; ffmpeg for GIFs).
- `build.py` (02-05) - generates the SVG(s) from `raven.svg`; 02 also samples the
  silhouette into glyphs and writes `glyphs.txt`; 04 prints the tray frame tables.
- `avd-*.xml` (01, 05) - AnimatedVectorDrawable sketches for Android drawable surfaces
  (well-formed, not compiled here).
- `README.md` - concept, timing table, resting state, reduced motion, where it plays,
  strengths, weaknesses, relation to the mark and palette, and what the revision changed.

## House motion rules applied throughout

- Micro-motion in the 150-400 ms band (blink 320 ms, badge pop 240 ms, slide 300 ms);
  arrivals `cubic-bezier(0.2, 0, 0, 1)`, departures ease-in, symmetric `(0.45, 0, 0.55, 1)`
  for oscillation. No overshoots anywhere (the launch stretch and the badge overshoot
  were removed in revision).
- Nothing loops at full energy: the blink is a 12 s cycle with three events, the flight
  rests 2 s in 5, the pulse plays twice and stops, the cursor breathes on the apps'
  stepped 1.6 s PulseDot table.
- Monochrome: every file uses one `--ink` variable (`#161310`, or `#E8E2DA` on
  `#12100F`), declared on the `svg` element so an inlined copy cannot override a host
  page's variable; no accent colour anywhere. No emoji; the terminal block passes
  `tools/asciicheck.py`.
- **The resting state is the mark.** In every file the values that apply when no
  animation runs are the finished state: the static mark (01, 02, 03), the ATTENTION icon
  (04), a static indicator (05). That is what renderers that apply CSS but no animations
  show: GitHub's file thumbnails and social cards, librsvg (GNOME file managers, many
  thumbnailers), Batik, Android's vector importer. A live renderer screenshotted at load
  shows the first frame instead, which for 02 is empty by design (use `poster.png`).
- `@media (prefers-reduced-motion: reduce)` in every SVG degrades to that resting state.
  Observed under Chromium emulation: honoured for inline SVG and for the file opened
  directly; **not honoured inside `<img>`** (01, 02 and 03 all keep animating with the
  preference on). So: inline SVG on the docs site where the query works; `poster.png` in
  the README with the animated file behind a link if motion sensitivity matters; the
  apps use their own reduce-motion setting.

## What was verified, and where

- CSS animation inside an SVG `<style>` plays in `<img>` in Chromium: a file-hosted page
  embedding `anim.svg` was screenshotted on a timer; 01 shows the 100 / 60 / 160 ms blink
  (103 → 127 → 124 → 48 → 25 → 9 → 0 px differ from the open frame at 90-321 ms), 02 and
  03 differ from their final / rest frames by thousands of pixels mid-animation.
- Firefox, Safari and GitHub's camo proxy: not tested (only Chromium is installed here).
  The `<img>` and reduced-motion statements above are Chromium observations.
- Rest frames: 03's animated rest frame has the same ink bounding box as 01's at 256 px
  (29, 70, 227, 188) and is pixel-identical with animations disabled; 02's resting tiles
  at 256 / 64 / 32 / 16 are the canonical mark.
- Every preview, sprite sheet and GIF was rendered with Chromium and looked at; scratch
  renders of the rounds (lid variants, seam tests, font tests, cut instants, edge scans)
  are under the session scratchpad `renders/anim-vector/rev/`.

## Honest limits

- 01 and 05(b) only read at hero sizes; 02 needs 160 px or more; 04 fixes nothing about
  the mark at 16 px (the badge carries the cue there; the ring is a two-to-three-tick
  halo). 03 introduces new geometry (the flight silhouette) that must be redrawn if the
  mark changes, and its two body swaps are cuts, not morphs. 02's 14 shade glyphs are
  still font-dependent for the 330 ms before the hand-over; the 79 block cells are not.
- Capturing: a paused animation seeked to exactly `currentTime = 0` is treated by
  Chromium as not started, so the compositor keeps the pre-seek frame. `window.seek(t)`
  therefore clamps to 1 ms; frames labelled `t=0.00s` are 1 ms in, which is visually
  identical.

## Revision (after the creative-director review)

Fixed in place, same ids and file names: the blank resting state of 02, its grey
crossfade and font-striped block; 03's displaced rest frame, top-edge wing clipping,
doubled no-animation fallback and dissolve hand-overs; 04's misleading 24 / 16 px rows,
missing IDLE → ATTENTION slide, IDLE resting state and flickering overshoot; 05's second
"working" rhythm, cursor proportion, petal feather and sub-pixel pupil; `:root` variables
in every file; the reduced-motion and timing claims in 01. Added: dark-ground previews,
resting-state tiles, `poster.png` for every variation, GIF fallbacks for 01 and 02, AVD
sketches for 01 and 05c, an edge scan in 03's capture, a `?static=1` page mode, and
the renderer / `<img>` findings above. Declined, with the measurement in 01's README:
clipping the blink lid to the eye hole (it rings). Withdrawn: 02 as a CLI banner (the
CLI is 7-bit ASCII; that is the ascii dimension's job), 03 as a README hero, 03's 32 px
claim.
