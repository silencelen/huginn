# mark-04-pixel — the ASCII-native raven

**Look at:** `preview.png`

## Concept

One drawing, three outputs. The raven is designed on a coarse pixel grid
(`grid.txt`) and *everything* is generated from it: the vector mark is the
grid as one path of unit squares with `shape-rendering="crispEdges"`, the
terminal art is the same grid read two rows per character (half-block, or
its pure-ASCII stand-in) or 2x4 pixels per character (braille), and the
animation frames are the grid with a few cells changed. There is no
interpretation step between the icon in the system tray and the banner in
the terminal: they are the same cells.

Two masters, one drawing. `m16` (16x16; the bird is 16 wide x 12 tall) is the
profile raven of the current mark on a grid it can survive on: bill right,
perched, no legs, eye as a ground cell, a long bill one row thick at the tip
and two at the base, a hackle bump at the throat, a wedge tail lower-left.
`m32` is the strict 2x of `m16` with its 2-cell stair-steps smoothed to
1-cell steps, the bill tapered 4 rows to 1 with the tip dropped one row (the
hook), a 2x2 eye and a pointed tail. Put the two side by side at 32 px and
they are the same bird.

## Which terminal form goes where

The brief's addendum makes the CLI clients (`client/huginn.sh`, `huginn.ps1`)
7-bit ASCII only. So:

| Form | Encoding | Where | Where not |
|---|---|---|---|
| `ascii-7bit*.txt` | 7-bit ASCII | the CLI clients (help raven, banner, speaking tick), anything shipped over `scp` | — |
| `ascii-halfblock*.txt` | Unicode | tmux pane, `huginn-status`, the apps' terminal view: anything that draws text at line-height 1.0 | README and docs: GitHub's code blocks add ~45 % line spacing and the bird separates into stripes (`preview.png`, "lh 1.45") |
| `ascii-braille.txt` | Unicode | README, docs, web code blocks, tmux: it survives line spacing because every row has its own glyph, and its ground is transparent | the CLI clients (non-ASCII) |

The half-block files are framed because a half-block block pads its ground
with spaces: unframed, short lines end in trailing spaces, which the
terminal rule forbids. Braille pads with blank braille (U+2800) and needs no
frame. The 7-bit files are framed with `+-|` for the same reason.

## Sizes: the integer rule

A pixel grid is exact only at integer multiples of its cell count. At any
other size a renderer makes some rows 1 px and some 2 px (`preview.png`,
"m16 svg at 24", "m32 svg at 48"). The rule for every surface is therefore
*scale by an integer, pad the rest* (`grid2png.py` does exactly that):

| Surface | Sizes | What is exact |
|---|---|---|
| Desktop tray at 100 / 200 % | 16, 32 | `m16`, `m32` native |
| Desktop tray at 125 / 150 % | 20, 24 | not exact when scaled; `png/tray-20`, `-24` pad a 1x `m16` instead (the raven is then 16 px in a 24 px slot, i.e. smaller than a smooth mark would be) |
| Windows `.ico` | 16, 32, 48, 256 | `m16` 1x, `m32` 1x, `m16` 3x (or `m32` 1x padded), `m32` 8x: all exact |
| Android adaptive foreground | 108, 162, 216, 324, 432 | `m32` at 2/3/4/6/8x in a 54-cell canvas: all exact (`png/adaptive-fg-*`) |
| Android notification (24 dp) | 24, 36, 48, 72, 96 | `m16` 1x+pad, 2x+pad, 3x, 4x+pad, 6x: exact, with uneven margins at 24 and 72 |
| Desktop tile with a 10 % inset (40 cells) | 40, 80, 120, 160 ... | exact at multiples of 40 only, **not** at 48 or 256: use `grid2png.py --ground bone` there |
| Anything above 64 | | `m32` at the nearest integer multiple; it is chunky by design |

## Intended uses

- **Terminal**: `ascii-braille.txt` at the top of the README and in docs;
  `ascii-halfblock.txt` as the banner in tmux / `huginn-status` where
  line-height is 1.0; `ascii-7bit.txt` (8 rows) as the CLI help raven and
  `ascii-7bit-32.txt` (16 rows) as a CLI banner if 18 lines is acceptable.
  No one-row status-line glyph is shipped: a 1x3 braille raven and a slice
  of the banner were both rendered in a tmux status-line mock and neither
  reads as anything; a status line should carry a state dot or the ASCII
  eye-and-bill (`(o)>`) that the CLI already uses.
- **Tray / notification / favicon at 16 and 32**: `m16` and `m32` native,
  with no anti-aliasing at all; at 20 / 24 the padded PNGs.
- **App icon**: `mark-04-pixel-tile.svg` is the adaptive-icon canvas; the
  launcher mask crops it to the inner 72, where the raven fills 89 % (see
  "launcher mask" in `preview.png`).
- **Animation**: `m16` / `m16-blink` is an idle blink; `m32` / `m32-call` is
  a "speaking" tick while a session streams. Because frames are grids they
  animate identically as SVG (swap paths), as half-block or 7-bit text
  (reprint the block) and as braille. The motion budget from the brief
  (stepped, ~6 frames/s) is more than enough: a blink is two frames.

## Strengths

- Cohesion across surfaces is structural, not stylistic: the tray icon, the
  terminal banner and the CLI help raven are literally the same cells.
- Pixel-exact at 16 and 32, at every Android density of the adaptive icon
  and at every `.ico` size; works in one colour on any ground.
- Terminal-native by construction, which is what the owner asked for ("ASCII
  art and animation") and what no smooth mark can honestly claim; it is the
  only direction in the set that ships a CLI-safe 7-bit raven.
- The grid is the source of truth and is trivially editable in a text
  editor; the generators are small, dependency-free Python, and every file
  in this folder regenerates from `grid.txt` byte for byte.

## Weaknesses

- Pixel-exactness is an integer-scale property. At a 125 / 150 % desktop
  tray (20 / 24 px) and at any size that is not a multiple of the grid the
  mark is either ragged (scaled) or small (padded); a smooth mark degrades
  more gracefully exactly there. The 10 %-inset desktop tile is never exact
  at 48 or 256.
- `m16` reads as a raven at 16 only because of the long bill and the wedge
  tail; crow, jackdaw and rook are all possible readings. `m32` reads raven
  from 32 up.
- Chunky above 64 px by design; next to the smooth current mark it reads
  retro. The 512 px cells in `preview.png` are the honest look of a hero.
- Half-block art needs a terminal that draws `▀▄█` edge to edge at
  line-height 1.0. In Chromium with DejaVu Sans Mono and Liberation Mono the
  cells show hairline vertical seams even at line-height 1.0 (visible in
  `preview.png`); real terminal emulators generally draw block glyphs as
  full cells, but that was not verified here. On GitHub the half-block
  banner breaks into stripes; use braille there.
- The 8-row 7-bit raven is coarse: `"` and `_` are thin stand-ins for half
  cells, the bill is a row of underscores and the eye merges with the crown.
  It is a recognisable bird with a bill, not a good drawing. The 16-row
  7-bit `m32` reads well but is tall for a CLI.
- No legs, like the current mark, so it is "perched" only by implication.

## Relation to the current mark and palette

Same raven, same pose (profile, bill right, perched, feathers over feet),
same ink `#161310` / bone `#E8E2DA`, same rule that the eye is a hole. What
changes is the rendering model: the current mark is a smooth evenodd path
that earns its shape only below 32 px; this one is a grid that is exact at
16 and 32 and chunky above. If chosen, `raven.svg` would be replaced by
`grid.txt` as the canonical source and `generate.sh` would call
`grid2svg.py` and `grid2png.py`.

## Revision

After review: `m16` was redrawn (the stubby 3-row bill that read as a duck
is now a long bill, one row at the tip, with a hackle bump and a longer
body) and `m32` is now built from the 2x of that `m16` (flat crown, bill
tapered 4 rows to 1 with a hooked tip, breast cut back), so the "one
drawing" claim holds. Added: an `ascii` mode in `grid2text.py` and 7-bit
files for the CLI; `grid2png.py` and the padded tray / adaptive-foreground
PNG sets with the integer-scale rule stated above; blink and call frames as
shipped SVG and text files (the call frame now hinges the lower mandible
with a wedge-shaped gap) and their commands in `grid.txt`; the 16-row `m32`
half-block banner (the 8-row `m16` one is now `-small`); the inverse files
regenerated with no padding; the tile moved to the 54-cell adaptive canvas
with the set's 22.5 % radius. Removed: the claim that one line of the
banner reads as a bird, and the half-block-for-README recommendation. The
non-integer renders (20 / 24 / 48) and the line-height-1.45 render are in
`preview.png` as the reason for the rules above.
