# Huginn

Claude Code on a server you own, reached from a terminal client (bash, PowerShell, Termux),
huginn core (Go), a Compose desktop app and an Android app. Start with
[docs/dev/README.md](docs/dev/README.md) for the repo map and
[docs/dev/architecture.md](docs/dev/architecture.md) for how the pieces fit.

## Build and test gates

- Daemon: `cd server/appd && node --test test/*.test.js` (no dependencies; floors in
  `scripts/test-floors.env`).
- Clients: `scripts/test-client.sh` (needs `pwsh` for the PowerShell half).
- Core: `cd core && go vet ./... && go test ./...`; end to end: `bash core/test/e2e.sh`.
- Kotlin: `cd mobile && ./gradlew :core:jvmTest :core:testDebugUnitTest :ui:jvmTest
  :app:testDebugUnitTest :app-desktop:test`. Needs the Android SDK and
  `mobile/app/google-services.json` (copy the `.example`).

## Rules

- `client/huginn.sh` and `client/huginn.ps1` are a pair and print 7-bit ASCII only. Help text is
  generated from `client/help-table.txt` (`node scripts/gen-help.js`). After changing a client
  file, refresh `core/internal/clientkit/files/*.txt` or the drift test fails.
- No real addresses, host names, accounts, keys or tokens in code, tests or docs: use
  `192.0.2.x`, `example.net`, `alex`-style placeholders.
- A new test must fail on the old code.
- Kotlin goes in the lowest module that can hold it (`:core` → `:ui` → the app shells); see
  [docs/dev/kotlin-clients.md](docs/dev/kotlin-clients.md).

## Brand and UI

The visual identity is decided; do not improvise colours, type or state words.

- `assets/brand/BRAND.md`: the rules (mark, tile, terminal art, tokens, type, motion, surfaces,
  voice).
- `assets/brand/design-card.html`: the one-page reference, generated by
  `python3 assets/brand/design-card.py` from the token, state and mark files; regenerate it after
  changing any of them.
- State language in code: `mobile/ui/.../theme/StateColors.kt` is the one place a state maps to a
  colour or a word (working · needs you · waiting · shell · ok · error · info). Needs-you is the
  lit accent, never `colorScheme.error`.
